# ParkingPlanet Development Instructions

## Project Overview

ParkingPlanet is a React Native parking app built with Expo, implementing modern features for finding, booking, and managing parking spots with EV charging capabilities.

## Technology Stack

- **Framework**: React Native with Expo SDK 54
- **Navigation**: Expo Router (file-based routing)
- **State Management**: Zustand (lightweight, React 19 compatible)
- **Maps**: React Native Maps with platform-specific providers (Google on Android, Apple on iOS)
- **UI Overlay**: react-native-modal (modern replacement for react-native-elements Overlay)
- **Styling**: React Native StyleSheet with Dimensions-based responsive design
- **Icons**: Expo Vector Icons (Ionicons, FontAwesome, MaterialCommunityIcons)
- **Blur Effects**: expo-blur for modern iOS look

## Data Model

See `docs/DATA_MODEL.md` for comprehensive schema documentation.

### Current Implementation

- **Status**: Mock data from `model/mockLocations.json`
- **Locations**: 4 parking facilities with multiple lots
- **Structure**: Full GraphQL schema support for future AWS Amplify integration

### Navigation Structure

- **Root Layout** (`app/_layout.tsx`): Stack layout that loads the main drawer group
- **Drawer Layout** (`app/(drawer)/_layout.tsx`): Drawer navigator wrapper for app screens
- **Driver Flow** (`app/(drawer)/driver/index.tsx`): Main map screen at `/driver`
- **Host Flow** (`app/(drawer)/host/_layout.tsx`): Host stack under the global drawer at `/host`
- **Search Screen** (`app/(drawer)/driver/search.tsx`): Search screen at `/driver/search`
- **Drawer Routes**: built from file names, not layout-group folder names
  - `/driver` → `app/(drawer)/driver/index.tsx`
  - `/host` → `app/(drawer)/host/(tabs)/index.tsx`
  - `/host/calendar` → `app/(drawer)/host/(tabs)/calendar.tsx`
  - `/host/reservations` → `app/(drawer)/host/(tabs)/reservations.tsx`
  - `/host/update-avl` → `app/(drawer)/host/update-avl.tsx`
  - `/driver/search` → `app/(drawer)/driver/search.tsx`
  - `/driver/filter` → `app/(drawer)/driver/filter.tsx`
  - `/driver/placeDetail` → `app/(drawer)/driver/placeDetail.tsx`
  - `/profile` → `app/(drawer)/profile/index.tsx`
  - `/(drawer)` group folder names are not part of public route paths

## State Management with Zustand

### Store Location: `src/store.js`

```javascript
export const useLocationStore = create((set) => ({
  // States
  originDetails: { location, viewport, description },
  destinationDetails: { location, viewport, description },
  mapBounds: { viewport },
  timeSetting: { startTime, duration },

  // Setters
  setOriginDetails: (details) => set({ originDetails: details }),
  setDestinationDetails: (details) => set({ destinationDetails: details }),
  setMapBounds: (bounds) => set({ mapBounds: bounds }),
  setTimeSetting: (setting) => set({ timeSetting: setting }),
}));
```

### Host Store Location: `src/hostStore.js`

```javascript
export const useHostStore = create((set, get) => ({
  hostProfile: { hostSub: null, hostName: "" },
  hostLotState: { hostSub: null, hostName: "", locations: [] },
  listingData: { type: "", addrLoc: "", lat: null, lng: null, nrOfLots: 1, hrPrice: 0, locName: "" },
  checkedPostIndex: 0,
  showLocationsList: false,
  hydrateHostData: (payload) => set(...),
  selectLocation: (index) => set(...),
}));
```

Host state stays separate from the driver location store. Do not place host listing or host identity state into `src/store.js`.

### Usage Pattern

```javascript
// Selector-based access (recommended for performance)
const destination = useLocationStore((state) => state.destinationDetails);
const setDestination = useLocationStore((state) => state.setDestinationDetails);
```

## Key Components

### Navigation

- **CustomDrawer** (`components/drawer/CustomDrawer.js`): Drawer menu UI
- **HeaderTabs** (`components/home/HeaderTabs.js`): Tab switching in header
- Uses `navigation.openDrawer()` for drawer control

### Modal Layout

- **LiquidGlassModal** (`components/modals/LiquidGlassModal.tsx`): reusable blur overlay layout for inner screens
  - Accepts `children`, `height`, and `heightPercent` so modals can render at varying heights
  - Supports drag-to-dismiss by swiping the sheet down
  - Provides an outside-tap backdrop to close the modal
  - Used by `/profile` to render `PaymentMethodScreen`
  - Recommended modal heights:
    - Payment Method: `50%`
    - Card Details: `70%`
    - Confirmation: `45%`

### Map & Location

- **EMap** (`screens/EMap.js`): Interactive map with location markers and horizontal carousel
  - **Marker Selection**: Pressing markers shows corresponding PostCard in carousel
  - **Carousel Snapping**: Proper `snapToInterval` calculation based on card dimensions
  - **Performance**: Optimized FlatList with `getItemLayout` and limited render batches
  - **Cross-Platform**: Platform-specific map providers and marker rendering
  - Uses mock data from `model/mockLocations.json`
  - Platform-specific map providers
  - Custom markers with price display
- **CustomMarker** (`components/CustomMarker.js`): Individual location markers
- **LocMarker** (`components/LocMarker.js`): User location marker (search here)

### Search

- **SearchBar** (`components/home/SearchBar.js`): Google Places autocomplete
  - Uses `EXPO_PUBLIC_GOOGLE_MAPS_APIKEY` from `.env`
  - Updates destination in Zustand store
  - Mock implementation: returns hardcoded results if API key missing

### Booking Flow

- **PostCard** (`components/home/Post/PostCard.js`): Location preview card
  - Shows location name, price, amenities
  - "Book now" button navigates to PlaceDetail with post data
- **PlaceDetail** (`app/placeDetail.tsx`): Detailed booking interface
  - LotsCarousel: Select specific parking spot
  - ListingTabs: Information, Reviews, How to park
  - TimeReg modal: Select booking duration for the active lot
  - FooterActionBar: Confirm booking and display lot-specific duration
  - Uses local `lotTimes` state so each lot preserves its own booking window

- **LotsCarousel** (`components/lots/LotsCarousel.js`): Parking spot carousel
  - **Availability Logic**: Uses `useCheckAvailability` hook from `global/utils/useCheckAvailability.js`
  - **Status Detection**:
    - Compares current time against `Transactions`
    - Checks `startBooking` and `endBooking` timestamps
    - Returns 'Available' or 'Busy' status
  - **Visual Indicators**:
    - `Green` (#4CAF50): Lot is available for booking
    - `Orange` (#FF9800): Lot is currently occupied
    - **Car Image**: Shows car silhouette (`carTopV_W.png`) when lot is 'Busy'
  - **Data Flow**:
    - Receives `lotState` prop with full Lot data including Transactions array
    - Each Transaction contains `startBooking` and `endBooking` ISO timestamps
    - Checks if current time falls within any active booking window
  - **Performance**: Optimized for 50+ carousel items with `initialNumToRender: 3`
- **FooterActionBar** (`components/footerNavs/FooterActionBar.js`): Booking actions
  - Shows time selection
  - Platform-aware rendering (iOS blur, Android dark overlay)
  - "Book now" button with pricing
  - Uses Expo Router for navigation

### Haptic Feedback System

- **HapticButton** (`components/HapticButton.tsx`): Reusable haptic component
  - Wraps `TouchableOpacity` with automatic haptic feedback
  - **Usage**: Replace `TouchableOpacity` with `HapticButton` for interactive elements
  - **Props**:
    - `hapticStyle`: `Haptics.ImpactFeedbackStyle.Light | Medium | Heavy` (default: Light)
    - `onPress`: Handler function
    - Inherits all `TouchableOpacity` props
  - **Platform Support**:
    - **iOS**: Uses impact feedback styles
    - **Android**: Uses notification feedback (selection)
    - Gracefully handles unsupported platforms with try-catch
- **BackBtn** (`components/btns/BackBtn.js`): Back navigation with haptics
  - Uses `HapticButton` for consistent feedback
  - Router integration with `useRouter().back()`
  - Reusable across all screens needing back navigation

### Availability Checking Hook

- **useCheckAvailability** (`global/utils/useCheckAvailability.js`): Utility hook
  - **Function**: `getAvailabilityStatus(transactions, preferredTime)`
  - **Parameters**:
    - `transactions`: Array of transaction objects with `startBooking`/`endBooking`
    - `preferredTime`: ISO timestamp string (defaults to current time)
  - **Logic**:
    - Checks up to last 5 transactions (sorted by recency)
    - Returns 'Busy' if any transaction overlaps with preferred time
    - Returns 'Available' if no overlaps found
  - **Example**:
    ```javascript
    const { getAvailabilityStatus } = useCheckAvailability();
    const status = getAvailabilityStatus(
      lot.Transactions?.items,
      new Date().toISOString(),
    );
    // Returns: 'Available' or 'Busy'
    ```

## EMap Component Details

### Overview

Interactive map component with location markers and horizontal carousel for parking spot selection.

### Key Features

- **Map Display**: React Native Maps with platform-specific providers (Google on Android, Apple on iOS)
- **Marker Interaction**: Custom markers showing hourly rates with selection states
- **Carousel Integration**: Horizontal FlatList showing PostCard components for selected locations
- **State Management**: Uses Zustand store for origin/destination/map bounds synchronization
- **Performance**: Optimized with `initialNumToRender={2}`, `maxToRenderPerBatch={2}`, `getItemLayout`

### Data Flow

- **Input**: `posts` array (real data) or falls back to `mockLocations.locations`
- **Marker Press**: Sets `selPostId`, triggers carousel scroll to matching PostCard index
- **Carousel Scroll**: Updates `selPostId` via `onViewableItemsChanged` callback
- **Map Animation**: Automatically centers camera on selected location

### Carousel Configuration

- **Card Dimensions**: `CARD_WIDTH = width * 0.9`, `CARD_SPACING = CARD_WIDTH + CARD_MARGIN`
- **Snapping**: `snapToInterval={CARD_SPACING}`, `snapToAlignment='start'`, `pagingEnabled={false}`
- **Performance**: `scrollEventThrottle={16}`, `decelerationRate='fast'`
- **Viewability**: `itemVisiblePercentThreshold: 70` for accurate card detection

### Marker Selection Logic

```javascript
// Marker press handler
onPress={() => setSelPostId(markerId)}

// Find index and scroll carousel
const index = displayPosts.findIndex(marker => marker.id === selPostId);
_carousel.current.scrollToIndex({ index, animated: true });

// Animate map to marker location
_map.current.animateToRegion({
  latitude: selMarker.lat,
  longitude: selMarker.lng,
  latitudeDelta: 0.09,
  longitudeDelta: 0.035
});
```

### Performance Optimizations

- `getItemLayout` provides efficient scrolling calculations
- `contentContainerStyle` with horizontal padding centers first/last cards
- `onScrollToIndexFailed` handles edge cases gracefully
- Limited initial render count prevents performance issues with large datasets

### Cross-Platform Considerations

- Map provider: `PROVIDER_GOOGLE` on Android, native provider on iOS
- Custom dark map styling applied consistently
- Platform-specific marker clustering and rendering optimizations

## Performance Tips

1. **Memoization**: Use `useCallback` for event handlers
2. **Lazy Imports**: Don't import unused components
3. **FlatList**: Always provide `keyExtractor` and `initialNumToRender`
4. **Navigator**: Use `presentation: 'modal'` fo screens that should slide up
5. **Images**: Use appropriate size images, compress before adding
